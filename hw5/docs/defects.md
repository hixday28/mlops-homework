# Пять дефектов первого LoRA-рана

Вход — собственные тензоры из ДЗ 4: 1267 train и 111 val. Файлы скопированы без изменений; test не используется. Оба варианта прошли одну полную эпоху, по 159 шагов оптимизатора, без ограничения max_steps. Learning rate 2e-4, ранг 8, alpha 16, batch_size 1 × grad_accum 8. Данные и токенизатор совпадают с ДЗ 4.

## 1. Не было валидации

В заготовке base_val равнялся None, список curve_val оставался пустым. В логе было только обучение: нельзя было увидеть переобучение или сравнить адаптер с базой.

Добавлен замер до первого шага. Матрица B у нового LoRA равна нулю, поэтому эта точка соответствует базовой модели. Затем оценка выполняется каждые 10 шагов и на последнем шаге, на одних и тех же 111 примерах. Loss val взвешивается числом позиций labels после causal shift, которые не равны −100. Train усредняется по примерам группы накопления: его абсолютные числа не сравниваются напрямую с val.

All_layers: 17 точек val, база **2.2742**, конец **1.9464**. Freeze14: база **2.2742**, конец **1.9810**. Обе кривые показаны в docs/curves.png. Числа получены нашим запуском; эталонные медицинские loss из лекции сюда не перенесены.

## 2. Завышенный learning rate

Исходный lr = 1e-2. У шага такой величины мог не быть NaN, но конечный адаптер становился хуже базы. Уменьшение lr до 2e-4 сделано в params.yaml; warmup, cosine schedule и clipping сохранены. Train и val проверяются отдельно. Плохой исходный прогон целиком не запускался, числа его расходимости не приписываются нашей машине.

В исправленном полном all_layers все 159 train-точек конечны, diverged = False. Val уменьшился с 2.2742 до 1.9464. Последняя train-точка — 2.0881; вывод о сходимости опирается на весь график и сравнение начала/конца в исходной проверке, а не на одну случайную точку.

## 3. Freeze14 не замораживал первые слои

Параметр freeze_first читался, но не передавался в LoraConfig. Оба варианта навешивали LoRA на все слои и давали одинаковое число обучаемых параметров.

Теперь layers_to_transform = range(freeze_first, num_hidden_layers). Для all_layers это 0–27, для freeze14 — 14–27. Базовые веса в обоих случаях заморожены; modules_to_save отсутствует, эмбеддинги и lm_head не включены в target_modules. Изменение числа слоёв действительно меняет модель, а не только имя каталога.

| Показатель | All_layers | Freeze14 |
|---|---:|---:|
| Обучаемые параметры | 5046272 | 2523136 |
| Доля параметров | 0.839% | 0.421% |
| Таймер обучения без val, с | 3544.9 | 3892.7 |
| Оценка по ходу обучения, с | 936.0 | 1051.5 |
| Секунд на шаг | 22.295 | 24.482 |
| Максимальный замер памяти, МиБ | 8423.5 | 8239.6 |
| Итоговый val loss | 1.9464 | 1.981 |
| LoRA-веса, МиБ | 19.30 | 9.65 |

Память измерялась через torch.mps.driver_allocated_memory после микрошагов; это максимум дискретных замеров, не гарантированный абсолютный пик. Время обучения исключает оценку; первоначальный замер базы выполнен до старта таймера. На производительность влияет нагрузка ноутбука. Freeze14 продолжился в том же процессе после разрядки и восстановления ноутбука: это показания таймера процесса, а не контролируемый бенчмарк скорости.

## 4. Адаптер нельзя было передать отдельно

В заготовке сохранялся только model.save_pretrained, а compare подхватывал токенизатор по имени базы из сети/кеша. На другой машине папка адаптера была неполной.

Теперь рядом с LoRA-весами сохраняются tokenizer.save_pretrained (включая шаблон), adapter_config.json и run_config.json. Compare загружает токенизатор из каталога адаптера, local_files_only=True. Ревизия базовой модели закреплена в конфиге. Все параметры генерации одинаковы для базы и адаптера: greedy и максимум 120 новых токенов.

Папка all_layers — 34.45 МиБ, из них LoRA-веса 19.30 МиБ; словарь токенизатора — отдельные файлы, эмбеддинги базы не копируются. Freeze14 — 24.8 МиБ. Для офлайн-запуска нужны веса базы в кеше HF: адаптер не заменяет базовую модель. Исходная проверка переносит папку, отключает сеть и сверяет пять ответов дословно.

Результат офлайн-проверки: **5 из 5 ответов совпали дословно** после загрузки из отдельной папки.

В docs/compare.md пять фиксированных вопросов по Docker, Git, Python и ML. Это демонстрация изменения ответов, а не оценка фактической точности на репрезентативном тесте. Все ответы получены генерацией; вручную они не исправлялись.

У адаптера есть слабые ответы: на вопрос о переобучении получился список импортов, а на вопрос о сохранении scikit-learn — общие слова без нужных команд. Более низкий val loss не означает, что каждый ответ стал правильнее.

## 5. Не был зафиксирован seed

В runtime.py помощник set_seed существовал, но обучение его не вызывало. Инициализация матриц LoRA и dropout менялись между процессами даже при одинаковом порядке данных.

Теперь seed 42 устанавливается до загрузки модели и создания LoRA: Python, NumPy и PyTorch; перемешивание батчей использует seed + epoch. Проверка выполняет два отдельных процесса по три шага и сравнивает кривые train после округления до четырёх знаков. Это воспроизводимость на нашей машине с одним uv.lock, а не обещание побитового совпадения на другой архитектуре.

В обоих независимых прогонах получена одинаковая кривая: **[2.4239, 2.1793, 2.4612]**. Все девять исходных проверок пройдены.

Отпечаток эксперимента включает код обучения, runtime, data, loss, config, секции параметров, uv.lock и содержимое обоих входных .pt. Исходный tests/check.sh не менялся: его отпечаток **06a02208c1f0**. После изменения обучения или входов требуется новый make train.

## Память и корректность расчёта

На обычном полном расчёте логитов пробный запуск получил MPS OOM. Поэтому logits считаются только для предсказываемых позиций ответа и блоками по 256 с checkpointing; контекст и attention_mask остаются полными. Labels сдвигаются ровно на один токен. Это тот же causal cross-entropy, а не сокращение выборки или длины ответов. Отдельный тест сравнивает значения loss и градиенты скрытых состояний/головы с плотным расчётом, включая замаскированное начало последовательностей и −100.

Последняя неполная группа накопления тоже делает optimizer.step: все 1267 примеров участвуют в эпохе. При train_tokens_processed = 768197 подтверждается весь вход из ДЗ 4. Часть токенов промпта замаскирована, но остаётся контекстом модели.
