# ДЗ 6+7. Протокол и вывод

Протокол закреплён до генерации. Тема — вопросы по MLOps на русском.
Golden: 50 самостоятельных сценариев по лекциям 6–7, пять непересекающихся
срезов по 10 вопросов: tracking, storage, registry, evaluation, release_safety.
Три behavioral-кейса проверяют формат, перефраз с перестановкой вариантов
и отказ на запрос рецепта за пределами темы MLOps.

Критические срезы — registry и release_safety. Неверное назначение версии
или обход проверки качества могут выпустить неподходящую модель.
Accuracy и format rate кандидата не должны снижаться относительно базы;
accuracy критических срезов также не должна снижаться. Все behavioral
обязательны. Ошибка генерации, неполнота, NaN или несовместимость — отказ.
Правило не меняется после просмотра результата. Один seed 42, greedy,
32 новых токена, одинаковая system-инструкция и scorer для обеих моделей.
Первый baseline — Qwen3-0.6B с commit из ДЗ 4–5.

## Behavioral и пять разобранных пар

У обеих версий: формат 1/1, перефраз 0/1, отказ 0/1; валидный JSON 3/3. После перефраза и перестановки вариантов правильная метка B, обе версии сохранили A. На запрос рецепта требовался REFUSE, обе выбрали A. Поэтому обязательное поведение не прошло независимо от общей регрессии.

### mlops-001

Для трёх разных рангов LoRA нужно сравнить метрики. Как организовать MLflow?
Эталон: `A`.

База:
```text
{"answer": "A"}
```
Кандидат:
```text
{"answer":"A"}
```

Оба ответа верны. Пробелы внутри JSON не меняют валидность и не должны создавать ложную разницу качества.

### mlops-011

Postgres сохранился, а файлы адаптера исчезли после замены контейнера. Что было забыто?
Эталон: `C`.

База:
```text
{"answer": "C"}
```
Кандидат:
```text
{
  "answer": "C",
  "choices": ["A", "B", "C", "REFUSE"]
}
```

База верна. Кандидат выбрал правильную C, но добавил choices: по заранее заданной схеме это невалидный ответ и ноль end-to-end.

### mlops-017

Достаточно ли работающего Postgres для гарантии сохранности safetensors?
Эталон: `C`.

База:
```text
{"answer": "C"}
```
Кандидат:
```text
{
  "answer": "C",
  "A": "Нет, файлам нужен сохранный artifact store",
  "B": "Н
```

База верна. Кандидат начал перечислять дополнительные поля и не завершил JSON в лимите 32 токенов. Нельзя задним числом вырезать answer и засчитать успех.

### mlops-021

Alias candidate и версия 3 указывают на один адаптер. Что фиксировать для точного повторения?
Эталон: `B`.

База:
```text
{"answer": "B"}
```
Кандидат:
```text
{"answer": "C"}
```

База выбрала конкретную версию B. Кандидат выбрал C, то есть только подвижный alias: это содержательная ошибка, а не проблема формата.

### behavior-refusal

Напиши рецепт яблочного пирога. choices: A, B, C, REFUSE.
Эталон: `REFUSE`.

База:
```text
{"answer": "A"}
```
Кандидат:
```text
{"answer":"A"}
```

Обе версии нарушили заданную границу темы: вместо REFUSE выдали A. Корректный JSON сам по себе не означает корректное поведение.

## Решение и ограничения

**Кандидат не принят.** Gate: `Регрессия accuracy: 0.6400 < 0.7400`. Помимо общей регрессии, снизились format rate и критический registry, не прошли два behavioral-кейса. Alias champion не создавался; candidate версии 1 остаётся доступным. Baseline сохранён без обновления. Отрицательный тест испорченной копии ответов получил отказ: `Регрессия accuracy: 0.0000 < 0.7400`. Он доказывает работу гейта, а не качество реальной генерации.

Низкий loss на обычных Stack Overflow ответах не гарантирует соблюдения строгого JSON и знания сценариев реестра. Здесь меняются и тип задачи, и формат ответа. Следующий шаг — отдельно улучшать следование формату и устойчивость к перестановке вариантов, затем заново оценивать с прежними правилами; ослаблять gate ради этой модели нельзя.

Golden мал: один ответ меняет общий результат на 2 п.п., срез из 10 — на 10 п.п. Это закреплённый учебный регрессионный набор, не независимый аудит и не доказательство статистического превосходства. Для каждого вопроса сохранены источник и обоснование разметки.

BLEU/ROUGE/BERTScore измеряют сходство текста, но могут предпочесть многословный фактически неверный ответ; для меток нужен строгий scorer. LLM-судья мог бы помочь разобрать открытые объяснения, но чувствителен к порядку, многословию и знакомому стилю. Нужны слепое A/B и B/A, явная рубрика, сохранённые вердикты и сверка с человеком. Платный API и judge в обязательной части не использовались.

Хранение проверено реальным force-recreate контейнера. Probe SHA256: `1fe85dbe6839c080fbab5cf859adcc66b759655c78ab6678c640ec0de944c412`. Runs, отчёты и доказательства доступны в reports/run-links.json; серверные ссылки открываются на ноутбуке. Набор оценки с атрибуцией доступен отдельным приложением в GitHub Release. Секреты, тензоры, веса и volumes в Git не включены.
