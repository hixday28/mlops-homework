# ДЗ 1. Окружение, инференс и бенчмарк

## Железо и выбор модели

- Apple M4, 10 ядер CPU, 16 GiB unified memory.
- macOS 26.5.2, arm64; ускоритель — Apple GPU через MPS.
- Python 3.12.14, torch 2.8.0, transformers 4.57.1, accelerate 1.11.0.
- Модель: `Qwen/Qwen3-0.6B`; dtype: `bfloat16`; устройство: `mps:0`.

Профиль по таблице лекции: Mac Apple Silicon, 16 ГБ+.
Для этой работы выбрана базовая модель курса. Она подходит для первого
инференса и оставляет запас памяти для последующих заданий. По таблице
для данного профиля возможна модель класса 1.7B, но её производительность
здесь не измерялась. Имя используемой модели задаётся в `params.yaml`.

## Результаты бенчмарка

Дата и время замера (UTC): `2026-09-08T15:38:17.263953+00:00`.
Источник чисел — `docs/bench.json`, сохранённый после запуска `make bench`.

| Метрика | Результат |
|---|---:|
| Время загрузки | 2.00 с |
| Скорость генерации, медиана | 27.96 токенов/с |
| Пиковая RSS процесса | 760.5 MiB |

| Прогон | Новых токенов | Время, с | Токенов/с |
|---|---:|---:|---:|
| 1 | 71 | 2.698659 | 26.31 |
| 2 | 71 | 2.538986 | 27.96 |
| 3 | 71 | 2.539408 | 27.96 |

Веса заранее скачаны. Загрузка токенизатора и модели измеряется отдельным
таймером до готовности устройства; импорт библиотек в него не входит.
Далее выполняется один прогрев и три измерения. Скорость каждого прогона —
фактическое число новых токенов, включая EOS, делённое на время генерации;
итоговая скорость — медиана. В таймер входит `model.generate` с prefill
и decode, но не токенизация, декодирование текста и запись JSON.
Перед замером и после генерации выполняется синхронизация MPS.

Пиковая RSS получена через `resource.getrusage(RUSAGE_SELF).ru_maxrss`:
на macOS байты делятся на 2²⁰, на Linux KiB делятся на 1024.
Это максимум RSS за жизнь процесса до конца измерений, включая загрузку
и прогрев, а не текущее потребление памяти. Поле `peak_rss_mb` имеет единицы
MiB и не отражает весь расход памяти GPU/unified memory.

Настройки: `temperature=0`, `seed=42`, `enable_thinking=false`,
`max_new_tokens=200`. Модель завершила ответ на 71 токене по EOS.
Ответ содержит два предложения вместо запрошенных трёх; результат
не редактировался. Повторные замеры скорости зависят от фоновой нагрузки.
Ревизия весов: `c1899de289a04d12100db370d81485cdf75e47ca`.

## Найденные и исправленные дефекты

### 1. Имя модели было захардкожено

В `model.py` использовалась строковая константа при загрузке,
в `generate.py` — при выводе, в `bench.py` — в отчёте. Изменение YAML
не меняло фактически загружаемую модель. Все три места теперь используют
`params['model']['name']`. Проверка подменяет конфиг, сверяет имя
загруженной модели и генерирует ею ответ, после чего восстанавливает YAML.

### 2. Зависимости не были зафиксированы

В `pyproject.toml` были только имена пакетов без версий, а lock-файл
отсутствовал. На другой машине установка могла получить несовместимые
версии. Добавлены точные версии через `==`, создан `uv.lock`, Python
ограничен версией 3.12. Установка и запуск выполняются с `--locked`.

### 3. Бенчмарк смешивал загрузку и генерацию

Таймер запускался до загрузки модели и не перезапускался в цикле;
прогрев отсутствовал, а `load_time` записывался как 0. Поэтому скорость
учитывала загрузку и предыдущие прогоны и была занижена.
Теперь загрузка измеряется отдельно, добавлен прогрев, каждый измеряемый
прогон получает собственный таймер, а итог считается медианой скоростей.
Для асинхронных операций GPU добавлена синхронизация. Корректный расчёт
пиковой RSS из заготовки сохранён.

### 4. Генерация не была воспроизводимой

В конфиге стояла температура 0.7, а функция установки seed не вызывалась.
Сэмплинг давал разные ответы при повторных запусках. Установлены
`temperature=0` и `do_sample=False`; перед загрузкой фиксируются seed
Python, NumPy и PyTorch. Используются `model.eval()`, `inference_mode()`
и детерминированные алгоритмы. Два независимых запуска сравниваются
побайтово через `diff` с проверкой кодов завершения.

## Проверка

```bash
make install
make generate
make bench
make check
```

`make check` проходит: проверяются отсутствие хардкода, подмена модели,
воспроизводимость, lock-файл и разделение замеров. Дополнительно проходят
пять модульных тестов (`make unit`). Конфиг восстанавливается и при
прерывании проверки. Требуемые каталоги `src/`, `data/`, `conf/`, `tests/`
присутствуют; зависимости зафиксированы в `uv.lock`.
