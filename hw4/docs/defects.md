# Четыре дефекта токенизации

Вход — собственный датасет вопросов по ML и инфраструктуре MLOps из ДЗ 3, версия `hw3-v2`: 1267 строк train и 111 строк val. JSONL скопированы без изменения содержимого. Test не используется при подборе длины. Проверяющий скрипт не менялся, его SHA256 начинается с `f2002c8c9519`.

## 1. Промпт попадал в лосс

В исходной функции `mask_prompt` возвращалась копия всех input_ids, а длина промпта принудительно равнялась нулю. Модель получала штраф за предсказание вопроса и системной инструкции, хотя задача — научиться отвечать. Маленький лосс в таком случае не доказывает качество ответа.

Теперь отдельно строится inference-префикс, его токены сверяются с началом полного диалога. При склейке BPE используется граница по символьным офсетам; пересекающий границу токен маскируется. На промпте labels равны −100, на ответе сохраняются ID токенов. После обрезки пример без обучаемых позиций отбрасывается.

При выбранном лимите в train 768197 токенов, из них 369338 под лоссом (48,08%). Остальные 398859 позиций промпта замаскированы. Проверка декодирует обучаемые позиции каждого из 1267 примеров и сравнивает с исходным ответом (для обрезанных — с его префиксом). В искусственном примере «Приве» / «Привет, мир» проверяется запасной путь BPE. В реальном train он не потребовался: 0 срабатываний.

## 2. Разные шаблоны обучения и инференса

Обучающий текст собирался вручную строкой TURN со спецтокенами, тогда как inference использовал шаблон токенизатора. В частности, такая ручная сборка не учитывала пустой блок рассуждений Qwen3 при выключенном thinking. Даже при похожем отображаемом тексте токены и граница ответа могли различаться.

Оба пути теперь вызывают шаблон модели в единственном модуле `src/prompt.py`. Для inference удаляется финальный ответ, добавляется заголовок генерации; можно передать и диалог, уже заканчивающийся вопросом. В обоих путях одинаковое `enable_thinking: false`, ревизия токенизатора закреплена в параметрах.

Проверка сверяет побайтовый префикс на всех 111 диалогах val. Дополнительно каждая запись при токенизации проверяется через startswith, иначе стадия останавливается. В исходниках нет вручную записанных спецтокенов ролей. Пустой блок thinking входит в замаскированный промпт, а не в целевой ответ.

## 3. Паддинг справа

Коллатор по умолчанию дополнял последовательности справа. Параметр left существовал в YAML, но не присваивался токенизатору. Это особенно заметно при генерации батча из примеров разной длины: последней позицией короткого примера оказывается pad.

Значение по умолчанию у коллатора заменено на left, настройка передаётся токенизатору и сохраняется в метаданных .pt и JSON. Дополнение динамическое, до самого длинного примера батча. Для добавленных позиций input_ids содержит pad_token_id, attention_mask — 0, labels — −100.

Проверка на батче из 2 неодинаковых примеров требует у короткого attention_mask от 0 до 1 и label −100 в первой позиции. Три места — параметры, метрики и коллатор — согласованы. Packing отключён: без блочной маски внимания соседние примеры могли бы влиять друг на друга. Выигрыш packing не заявляется.

## 4. Молчаливая обрезка

Функция truncation_stats возвращала пустой словарь. При исходных 232 токенах после исправления маски измерено 1130/1267 обрезанных train (89,19%) и 102/111 val (91,89%). У 642 train и 51 val ответ полностью исчезал. Эти числа получены отдельным запуском с лимитом 232, а не взяты из лекции.

Теперь длины и доля обрезанных считаются по всем входным примерам, включая отброшенные. При превышении неизменённого порога 5% стадия печатает WARNING, а проверка 5 завершается ошибкой. Счётчик потерянных ответов сохраняется отдельно.

По распределению train p99 = 2326 и max = 3563 выбран max_seq_len = 2560. После этого обрезаются 5/1267 train (0,39%) и 0/111 val; полностью потерянных ответов нет. Порог не повышался. Автоматический отчёт и metrics/tokenize.json создаёт стадия, руками они не редактируются.

Прогноз использует фактические 27,96 ток/с из `hw1/docs/bench.json`: три эпохи дают оптимистичную оценку 22,9 часа. Это скорость генерации; обучение с backward ориентировочно в 2–3 раза медленнее, то есть 45,8–68,7 часа. Реального обучения в ДЗ 4 не было, прогноз не является замером.
