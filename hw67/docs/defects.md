# Четыре дефекта учёта экспериментов

## 1. Разные модели смешивались в одном run

В заготовке один дочерний `all-candidates` оборачивал весь цикл, а параметры
логировались только при пустом run. Поэтому последние метрики и файлы могли
оказаться рядом с параметрами первого кандидата.

Теперь `start_run(name, nested=True)` находится внутри цикла конфигураций.
У текущего sweep `706a09a9455f44d89e1ffbe6d0870a0c` шесть разных дочерних runs, каждый
завершён и имеет четыре train-точки и val на шагах 0, 2, 4. Все шесть строк
`docs/comparison.csv` выгружены с сервера. Лучшая — `all-r8-high`,
val 2.278586. Прерванная при перезапуске ноутбука первая
попытка помечена KILLED и сохранена в истории; в сравнение она не включена.

## 2. Файлы исчезали после замены контейнера

Postgres уже был подключён к volume, но `/mlartifacts` оставался в слое
контейнера. База метаданных могла выжить, а веса и tokenizer — исчезнуть.

Добавлено `artifacts:/mlartifacts` к сервису mlflow. Проверка записала
случайный probe, сохранила его SHA256, выполнила `--force-recreate` только
сервиса mlflow и скачала тот же файл. Не использовался обычный restart.

Проверка прошла. Run: `5f3dc85a2c124d0ab568c4a2b0538a04`; SHA256 файла до и после:
`1fe85dbe6839c080fbab5cf859adcc66b759655c78ab6678c640ec0de944c412`. Доказательство — `reports/storage-check.json`.
Volume Postgres и artifact volume не удалялись.

## 3. Терялись версии train и val

В заготовке `provenance()` вычислял хеши данных, но sweep удалял все ключи
`data_*`. Нельзя было отличить модель на старом val от модели на новом.

Теперь полный provenance передаётся родителю и каждому кандидату. У всех
шести runs актуальные SHA256 кода, конфига и обоих тензоров; select сверяет
их с текущими файлами до регистрации. Тензоры совпадают с ДЗ 4 побайтно.

Train: `54f4b1ebfcb1cc39917bdcd4d64bb4ed99b0fd9e1c2031e6410bf26741120604`.
Val: `642e7c5b28280a8c05c1ab5d656c9b93eeef08211de8b9e39bc67a8e2a7a0363`.
Код src: `9b5cc250c8b367b8f8fb954925b88e63ed61896f88cc1057d1efbb6a777f0e1b`.
Git при старте: `3a105bfe3998e57ceb2fb3ebaf560adf4a92103c`. В момент старта был изменён
служебный путь DVC, поэтому `git_dirty=True`; фактические src и uv.lock
сохранены в артефактах runs. Версии данных также закреплены `inputs.dvc`.

## 4. Регистрация обходила loss-порог

`promote()` вычислял отношение val/base и сразу регистрировал модель,
не вызывая уже существующую функцию gate. В теге validation появлялось
passed независимо от порога.

Теперь `gate(run, threshold)` вызывается перед `register_model` и alias.
Она проверяет FINISHED, конечность метрик, положительный base и отношение.
У выбранного кандидата ratio = 0.880964, что проходит исходный порог 1.0.
Отдельная выданная проверка задаёт порог 0 и проверяет отказ без регистрации.

Alias candidate обозначает только прохождение части A. Качество ответов
проверяет отдельный `evaluation.solution.quality_gate`; он отказал:
`Регрессия accuracy: 0.6400 < 0.7400`. Champion не назначен. Испорченная копия ответов тоже
отклонена: `Регрессия accuracy: 0.0000 < 0.7400`; реальные ответы, веса и alias не менялись.

## Память и исходные тесты

Расчёт causal loss блоками перенесён из ДЗ 5: полный контекст и сдвиг labels
сохраняются, логиты словаря не создаются для замаскированных позиций.
Тензоры не обрезались заново ради короткого поиска. Бюджет одинаков у всех.

Скрипты tests/ не изменены. Их общий отпечаток — `c42ac7788026`.
Тесты scorer/gate используют синтетические ответы; измерения Qwen получены
отдельным реальным запуском evaluate, а не этими фикстурами.
