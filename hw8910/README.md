# ДЗ 8+9+10. Безопасный выпуск и API

Исправлены семь причин ошибок. 13 исходных тестов сохранены, добавлены девять
собственных проверок. **22/22 проходят на stdlib и FastAPI.** Восемь новых
проверок используют настоящие HTTP/subprocess, ещё одна — ошибку atomic replace.

API обслуживает настоящую **Qwen3-0.6B baseline** из ДЗ 6+7. Кандидат версии 1
не принят: accuracy 0.64 < 0.74. Нового обучения и ослабления gate нет.
Baseline импортирован как существующая точка отсчёта, ему не приписан новый PASS.

[Отчёт](REPORT.txt), [семь дефектов](defects.csv),
[замер](docs/benchmark.csv), [свидетельства](evidence).
Исходник — commit `e4904d7`, реализация — `553fa2e`.

## Установка и проверки

Python 3.12, uv. Для быстрых проверок модель, Docker, MLflow и Prefect server
не нужны. FastAPI/Prefect как библиотеки устанавливаются лёгким профилем.

```bash
cd hw8910
make install
make check
make check-broken  # намеренно ненулевой exit; поломка только во временной копии
```

`make check` выполняет 22 теста с каждым HTTP-драйвером, без весов.
Отпечаток исходного `test_release.py`: **09bd65e6b886**. Новые тесты не включены
в этот отпечаток. Красные/зелёные логи и source diff находятся в evidence.

Для проверки против настоящего исходного commit:

```bash
uv run --frozen --no-sync python tools/prove_regressions.py
```

Все девять новых проверок должны упасть на нарушениях исходника, а не на
ImportError. Дополнительно к повтору выпуска проверяется сбой журнала после
обновления указателя и восстановление без второго события.

## Настоящая модель и артефакты

```bash
make install-model
make materialize
make prefect-up
make flow          # ожидаемый отказ по качеству, ненулевой exit
make api-up
```

`materialize` читает существующий training artifact. Базовые веса берутся из
публичного HF по commit `c1899de289a04d12100db370d81485cdf75e47ca`. Файлы кандидата
доступны [отдельно в artifact store](https://github.com/hixday28/mlops-homework/releases/tag/hw8910-artifact)
и проверяются по SHA256 из `evidence/candidate-manifest.json`. Это отдельные
файлы артефакта, не часть Git/исходного архива. Не требуется доступ к моему
локальному MLflow. Сам адаптер для API не используется: он отклонён.

Golden и полный training-index при отсутствии автоматически восстанавливаются
из [приложения ДЗ 6+7](https://github.com/hixday28/mlops-homework/releases/tag/hw67-submission)
с проверкой SHA256. Полные исходные raw/eval отчёты уже находятся в hw67/reports.
При наличии исходного MLflow можно повторить чтение оттуда флагом
`--artifact-source mlflow`, используя окружение hw67 с MLflow 2.22.2.

Генерация выполняется с теми же библиотеками и условиями, что использовались
при оценке: MPS, bfloat16, исходный system/template, greedy, seed 42 и 32 токена.
Замена dtype, устройства, токенизатора или генерации не наследует этот допуск:
нужны новая оценка и связанный manifest. На другой платформе можно полностью
выполнить быстрые тесты; результаты реальной модели здесь измерены на Apple MPS.
Веса/venv/кеши/Prefect DB находятся в игнорируемых каталогах.

## Процесс, кеш и отказ

Граф: prepare-input → get-existing-artifact → check-complete-evaluation → publish.
Последняя задача не исполняется при отказе. Подготовка проверяет реальный JSONL,
шаблон и длины токенизатором. Веса не передаются между задачами.

```bash
uv run --frozen --no-sync python flow.py --workspace .real --fail-after-prepare --refresh-preparation
make flow
```

Первый запуск действительно выполняет подготовку и намеренно падает. Второй,
в другом процессе, показывает **Cached** и доходит до настоящего отказа gate.
`--refresh-preparation` нужен только для чистого начала повторной демонстрации.

Все девять автоматизированных опытов, включая замену входа по прежнему пути,
успешный STUB flow и восстановление журнала:

```bash
uv run --frozen --no-sync python tools/flow_experiments.py
```

Это изменяет только копию входа подготовки и затем восстанавливает её.
Исходный golden ДЗ 6+7 не меняется. Новый вход инвалидирует кеш и также
получает отказ из-за несовпадения с оценёнными данными. Фикстурный PASS
помечен STUB и не выдаётся за оценку Qwen.

## API и видео

После `make api-up`:

```bash
curl -s http://127.0.0.1:8091/health
curl -s http://127.0.0.1:8091/ready
curl -s http://127.0.0.1:8091/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Для чего нужен реестр моделей? A. Хранить версии моделей. B. Готовить пирог. choices: A, B, REFUSE.","max_new_tokens":32}'
curl -s -w '\nHTTP %{http_code}\n' http://127.0.0.1:8091/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"тест","max_new_tokens":100000}'
```

Последний запрос должен дать **422**, без вызова генерации. Настоящий API
принимает только лимит **32**, вход до 2048 символов и 512 токенов с шаблоном.
Прототип STUB допускает 1–32. Debug локального стенда: `/debug`; до и после
неверного запроса `calls` одинаков. `model_id` и `runtime_sha256` отражают
загруженную версию, а не новый файл указателя.

```bash
make api-restart
make benchmark
make api-stop
```

Замер выполняет 8 одинаковых запросов при concurrency=1 и те же 8 при 2.
Каждая попытка сохраняется, ошибки не удаляются. Измеряется полная задержка
JSON, не TTFT/ITL; выводы о p95 не делаются. В сохранённом прогоне: 8/8 и 8/8,
средняя задержка 0.633 и 1.858 с; второй режим медленнее и ждёт блокировку.

Видео 5–8 минут:

1. `make check`: два зелёных прогона по 22 теста. `make check-broken`: намеренный
   красный прогон, затем снова обычный `make check` без изменения рабочего кода.
2. [Prefect](http://127.0.0.1:4208): или сохранённые flow-логи — сбой после
   подготовки, Cached после повторного процесса, отказ gate, неизменный accepted.
3. `evidence/release-report.json` и `defects.csv`: связанный отказ и семь причин.
4. `make api-up`, health/ready, настоящий ответ с model_id/runtime_sha256 и 422.
5. `docs/benchmark.csv`, `evidence/requests.jsonl`: числа и очередь; STUB-проверка
   A → B → A в `test_http_loaded_version_restart_and_rollback` и логи.

Повторное обучение и повторная полная оценка для записи не нужны. Логи тяжёлых
опытов уже сохранены. Ссылку на своё видео добавьте при сдаче.

## Три триггера

| Изменение | Действие |
|---|---|
| Код | `make check`; если меняется генерация, полная оценка обеих версий |
| Данные | Проверка схемы/версии, content-key инвалидация; для нового golden — новая оценка, для train отдельно решается необходимость обучения |
| Новый адаптер | Проверка файлов/загрузки, полная оценка, прежний gate, публикация только после PASS |

`ci.example.yml` — только адаптированный шаблон. Выполнен локальный CI;
удалённый Actions и защита merge не заявляются.

Использованы механизмы [Prefect caching](https://docs.prefect.io/v3/how-to-guides/workflows/cache-workflow-steps)
и [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/).
Лицензия исходной Qwen — [Apache 2.0](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/LICENSE);
с артефактом сохраняются лицензия и происхождение.
